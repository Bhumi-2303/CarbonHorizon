Carbon Horizon
Learn Your Impact. Shape the Future.

Version: 2.0




1. Database Overview
Purpose
The Carbon Horizon database stores:


     • User accounts
     • Carbon assessments
     • Emission inputs
     • Simulations
     • Forecasts
     • Goals
     • Habit tracking
     • AI conversations
     • Carbon factor references

The schema is designed to:


     • Support MVP requirements
     • Maintain scientific traceability
     • Enable future scalability
     • Preserve historical assessment data
     • Support AI-powered recommendations




2. Database Technology
Development Database: SQLite


Production Database: PostgreSQL 16+


ORM: SQLAlchemy

11. Forecast Points Table
Table Name
forecast_points


Purpose
Stores forecast values dynamically.


Why This Table Exists

Instead of storing:


predicted_3_month predicted_6_month predicted_12_month


we store unlimited forecast points.


This supports:


     • 3 Months
     • 6 Months
     • 12 Months
     • 24 Months
     • Future Expansion

Fields

id UUID PRIMARY KEY


forecast_id UUID FOREIGN KEY → forecasts.id


month_offset INTEGER


predicted_emission FLOAT


created_at TIMESTAMP

21. Data Retention Policy
Assessment Data: Retained indefinitely


Simulation Data: Retained indefinitely


Habit Data: Retained indefinitely


AI Conversations: Retained for 24 months


Soft Deleted Accounts: Retained for 90 days


Audit Logs: Retained for 12 months

23. Schema Success Criteria
The database schema shall be considered successful if:


     • All MVP features are supported
     • Historical assessments remain traceable
     • Carbon factors are version-controlled
     • Forecasts support unlimited time horizons
     • Goal tracking operates correctly
     • Dashboard queries execute efficiently
     • Future feature expansion requires minimal schema changes
